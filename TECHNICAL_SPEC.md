# Техническое задание: магазин курсов с ИИ-консультантом

## 1. Назначение и границы этапа

Учебный пример для начинающих Python-разработчиков. Главная цель — показать, как подключать разные языковые модели через официальный Python-пакет `openai`, передавать контекст магазина и получать ответ на вопрос покупателя.

Первый этап завершился созданием этого документа, `AGENTS.md`, `.local.env`, `.local.env.example` и `.gitignore`. По следующему заданию пользователя приложение реализовано; команды запуска находятся в `README.md`, актуальный отчет — в `VERIFICATION.md`. Раздел 9 сохраняет исторические результаты первого этапа.

Будущее приложение запускается локально на FastAPI. Интерфейс — одна страница на русском языке с тремя карточками курсов и чатом. Использовать HTML, CSS и обычный JavaScript. База данных, ORM, Docker, регистрация, авторизация, личный кабинет, реальные заказы, платежный шлюз, RAG, векторный поиск и LangChain не нужны.

Единый источник сведений — обычные структуры Python в `courses.py`. Страница получает каталог через API; консультант получает те же данные в системном сообщении. Не дублировать цены и условия в HTML или тексте инструкции модели.

Цены целочисленные, валюта — `RUB`. Недели — ориентир самостоятельного прохождения; часы — примерная учебная нагрузка. Доступ к материалам — 12 месяцев. Условные способы оплаты — банковская карта и банковский перевод. Приложение не принимает деньги, не запрашивает платежные реквизиты и не оформляет заказы. На странице и в ответах об оплате явно показывать учебный характер сценария. Другие условия, например рассрочка, возврат, сертификат или сопровождение преподавателя, не заданы.

## 3. Интерфейс и поведение консультанта

На странице показать название магазина, три карточки со всеми сведениями о курсах, учебные условия и чат. Чат содержит историю, поле вопроса, кнопку «Отправить» и кнопку «Очистить чат». На время запроса отключать повторную отправку и показывать состояние ожидания. Ответы выводить обычным текстом через `textContent`, без исполнения HTML.

Консультант объясняет цену, содержание, длительность, рекомендует курс по целям и подготовке пользователя, сравнивает варианты и понимает уточнения вроде «А сколько он стоит?». Если цель или опыт неясны, задает короткий уточняющий вопрос. По фактам магазина опирается только на серверный каталог и условия. Не придумывает скидки, гарантии, реквизиты и факты о покупке. При отсутствии сведений сообщает об этом; на посторонние вопросы предлагает вернуться к выбору курса. Пользовательские сообщения не должны заменять системную инструкцию. Ограничение поведения через инструкцию модели не является абсолютной гарантией точности.

История хранится только в памяти страницы: без localStorage, базы данных и серверных сессий. Очистка и перезагрузка сбрасывают диалог. С запросом передавать последние 19 сообщений истории и новый вопрос: максимум 20 сообщений. После сокращения контекста старые сообщения могут оставаться видны на странице. При ошибке не добавлять вымышленный ответ ассистента; дать возможность повторить запрос. Не регистрировать содержимое диалогов в логах.

## 4. Архитектура и поток данных

```text
main.py                # FastAPI, Pydantic-модели и маршруты
courses.py             # Каталог и условия магазина
llm.py                 # Настройки, системная инструкция, OpenAI SDK
static/
    index.html
    styles.css
    app.js
tests/
    test_api.py
    test_llm.py
requirements.txt
README.md
TECHNICAL_SPEC.md
AGENTS.md
.local.env             # Локальный секрет; исключен из Git
.local.env.example     # Только заглушки
.gitignore
```

Поток чата: JavaScript → `POST /api/chat` → проверка Pydantic → `llm.get_chat_answer(messages)` → внешний API → текст ответа → JavaScript. `llm.py` импортирует каталог и условия из `courses.py`, добавляет их к системной инструкции. Клиент не передает системные сообщения, ключи, модель или адрес провайдера.

В `llm.py` использовать `AsyncOpenAI(api_key=..., base_url=..., timeout=30.0, max_retries=0)` и один вызов `await client.chat.completions.create(model=..., messages=...)`. Системная роль добавляется первой. Возвращать текст первой альтернативы; пустой результат считать ошибкой провайдера. Не использовать streaming, инструменты, агенты и специальные параметры отдельных моделей. По запросу об упрощении для новичков клиент создается внутри `async with` для каждого вопроса и автоматически закрывается после него, в том числе при ошибке. Глобальное состояние и отдельные функции управления клиентом не нужны. Отсутствие настроек не должно мешать выдаче каталога.

Настройки загружать через `python-dotenv` именно из `.local.env` рядом с `llm.py`: путь строить относительно `__file__`. Использовать `override=False`, чтобы переменные среды имели приоритет. Все четыре настройки обязательны; допустимые провайдеры: `openai`, `deepseek`, `qwen`, `yandex`. Не подставлять OpenAI-ключ при смене провайдера. Для демо разрешать только соответствующие HTTPS endpoint из раздела 6; несовпадение провайдера и адреса — ошибка конфигурации до отправки ключа.

## 5. Контракт HTTP API

### GET /

Возвращает `static/index.html`; файлы стилей и JavaScript доступны под `/static`. Приложение и страница работают с одного адреса, настройка CORS не нужна.

### GET /api/courses

Возвращает JSON-массив ровно из трех объектов. Поля: `id`, `title`, `description` — строки; `price` — положительное целое; `currency` — `RUB`; `duration_weeks`, `duration_hours` — положительные целые; `topics` — список строк. Общие условия отображаются на странице отдельным постоянным пояснением; их текст в интерфейсе должен соответствовать `courses.py`.

### POST /api/chat

Дополнительный маршрут `GET /api/terms` возвращает `SHOP_TERMS` из `courses.py`, чтобы интерфейс и консультант получали условия из одного источника без дублирования текста в HTML.

Запрос:

```json
{"messages": [{"role": "user", "content": "Какой курс подойдет новичку?"}]}
```

Успешный ответ, HTTP 200:

```json
{"answer": "Для начала подойдет курс «Основы Python»…"}
```

`messages`: от 1 до 20 элементов. `role`: только `user` или `assistant`; последнее сообщение — `user`. `content`: строка от 1 до 2 000 символов после удаления пробелов по краям. Пустые строки отклонять. Лишние поля запроса и сообщений запрещать. История из браузера не считается доверенным источником фактов магазина.

Ошибки валидации возвращать стандартным ответом FastAPI HTTP 422. Для ожидаемых ошибок чата возвращать `{"detail": "понятное сообщение"}`:

| Ситуация | HTTP | Сообщение пользователю |
|---|---:|---|
| Настройки отсутствуют или неверны | 503 | Чат не настроен. Проверьте настройки сервера. |
| Ключ отклонен, модель недоступна или квота исчерпана | 503 | Сервис модели недоступен. Проверьте ключ, модель и квоту на сервере. |
| Превышен лимит запросов без признака исчерпанной квоты | 429 | Слишком много запросов. Попробуйте позже. |
| Тайм-аут | 504 | Модель не ответила вовремя. Повторите запрос. |
| Ошибка соединения, внешний сбой или пустой ответ | 502 | Не удалось получить ответ модели. Попробуйте позже. |

Не возвращать сырой ответ ошибки провайдера и секреты. Для диагностики разрешены HTTP-статус и безопасный код ошибки без ключа и текста диалога. `GET /api/courses` продолжает работать при сбое чата. `/docs` предоставляет Swagger UI с описаниями маршрутов и примерами.

## 6. Конфигурация провайдеров

Официальный пакет `openai` — клиентская библиотека, а не общий ключ для разных сервисов. API OpenAI вызывает модели OpenAI; подписка на интерфейс ChatGPT не заменяет API-доступ. У каждого провайдера свои ключи, доступность моделей и квота. Примеры ниже не содержат реальных секретов.

OpenAI:

```dotenv
LLM_PROVIDER=openai
LLM_API_KEY=YOUR_OPENAI_API_KEY
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4.1-mini
```

DeepSeek:

```dotenv
LLM_PROVIDER=deepseek
LLM_API_KEY=YOUR_DEEPSEEK_API_KEY
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-flash
```

Qwen через Alibaba Cloud Model Studio, международный endpoint региона Сингапур:

```dotenv
LLM_PROVIDER=qwen
LLM_API_KEY=YOUR_MODEL_STUDIO_SINGAPORE_API_KEY
LLM_BASE_URL=https://dashscope-intl.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
```

Ключ Qwen должен соответствовать выбранному региону. Другие региональные endpoint в этот пример не входят. Для переключения заменить все четыре настройки и перезапустить FastAPI. Реальные значения хранить только в `.local.env`; образец `.local.env.example` содержит исключительно заглушки.

Источники для проверки адресов, моделей и SDK:
- [Официальный Python SDK OpenAI](https://developers.openai.com/api/reference/python).
- [Chat Completions](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create).
- [Документация DeepSeek](https://api-docs.deepseek.com/).
- [OpenAI-совместимый API Alibaba Cloud Model Studio](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope).

Chat Completions выбран ради общего учебного интерфейса совместимых провайдеров. Доступность конкретной модели в аккаунте подтверждается только реальным запросом. Статус проверки текущего этапа приведен в конце документа.

При реализации официальные страницы удалось загрузить через HTTPX: адреса проверены, для DeepSeek актуальный пример обновлен на `deepseek-flash`, для Qwen подтверждены `qwen-plus` и международный endpoint Сингапура. Доступ к моделям DeepSeek и Qwen в конкретном аккаунте без их ключей не проверен.

## 7. Зависимости, запуск и учебное объяснение

### Дополнение YandexGPT

Поддерживается четвертый провайдер `yandex` с endpoint `https://ai.api.cloud.yandex.net/v1`. К четырем основным настройкам добавляется обязательная для него `YANDEX_FOLDER_ID`. Пример модели: `gpt://YOUR_FOLDER_ID/yandexgpt/latest`. ID каталога должен быть непустым, не заглушкой и совпадать с каталогом в URI модели; неверная конфигурация отклоняется до обращения к SDK с HTTP 503. `load_settings()` возвращает `(key, base_url, model, project)`; `project` содержит ID каталога только для YandexGPT, для остальных провайдеров — `None`. Клиент создается с `project=project`.

Образец без секретов — `.local.env.yandex.example`. Существующий `.local.env` автоматически не переключается на YandexGPT. Справочник: [официальный пример Completions API](https://aistudio.yandex.ru/en/docs/ai-studio/operations/generation/completions-basic). Поддержка не требует новых библиотек, маршрутов или изменений браузерного интерфейса. Реальная проверка требует отдельного Yandex API-ключа.

Целевая версия — Python 3.11+. Зависимости будущего приложения: `fastapi`, `uvicorn`, `openai`, `python-dotenv`; для проверок — `pytest`, `httpx`. На этапе реализации выбрать совместимые версии, проверить установку и зафиксировать их в `requirements.txt`.

В README объяснить различие API, SDK, модели, ключа и `base_url`, путь вопроса от браузера до провайдера, назначение каждого файла и роль системного сообщения. Показать короткий фрагмент подключения из фактического `llm.py`. Не скрывать простое подключение за фабриками или иерархией классов.

## 8. Проверки и критерии приемки реализации

Автоматические тесты не обращаются к сети и не расходуют средства: подменять функцию ответа модели в тестах маршрута, а клиент SDK — в тестах `llm.py`.

- Каталог возвращает ровно три заданных курса с точными ценами и темами; страница использует этот API.
- Валидный запрос возвращает `answer`; история передается в исходном порядке, системная инструкция добавляется сервером и содержит каталог.
- Отклоняются пустая история, более 20 сообщений, пустой текст, текст длиннее 2 000 символов, роль `system`, последнее сообщение `assistant`, лишние поля.
- Проверяются все классы ошибок из таблицы, пустой ответ модели и работоспособность каталога без настроек чата.
- Настройки используют `.local.env`, переменные среды имеют приоритет; несовпадение адреса и провайдера отклоняется до обращения к SDK.
- Ручная проверка страницы: мобильная ширина, ожидание ответа, повтор после ошибки, очистка, сброс после перезагрузки, отсутствие исполнения HTML из ответа.
- Ручные диалоги с реальной моделью: цена Python, темы FastAPI, сравнение курсов, рекомендация новичку, уточнение «А сколько он длится?», способы оплаты, неизвестная скидка, просьба игнорировать каталог. Ответы должны соответствовать разделам 2–3.

Реальную проверку каждого провайдера запускать отдельно и только с его ключом; не включать ее в обычный запуск pytest. Отчет должен различать проверенный API-вызов, автоматические тесты с подменой и неподтвержденные интеграции. Публикация и эксплуатация в интернете в рамки демо не входят.
