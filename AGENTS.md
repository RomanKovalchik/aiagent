# Инструкции по проекту

## Назначение и текущий этап

Это учебный магазин трех курсов с ИИ-консультантом на FastAPI. Источник требований — `TECHNICAL_SPEC.md`. Приложение реализовано по отдельному заданию пользователя. Инструкции запуска находятся в `README.md`, фактические результаты проверки — в `VERIFICATION.md`.

## Понятность для начинающих

- Используйте Python 3.11+, FastAPI, HTML, CSS и обычный JavaScript.
- Предпочитайте короткие функции, ясные имена и прямой поток данных. Комментарии на русском объясняют причины решений.
- Сохраняйте плоскую структуру: `main.py`, `courses.py`, `llm.py`, `static/`, `tests/`.
- Не добавляйте БД, ORM, Docker, авторизацию, платежный шлюз, LangChain, RAG, фабрики и дополнительные слои без нового требования.
- Все операции с моделями и настройки SDK размещайте в `llm.py`. Используйте `AsyncOpenAI` и `chat.completions.create` без streaming.
- Каталог и условия в `courses.py` — единый источник сведений для API, страницы и контекста модели. Не дублируйте цены в HTML и системной инструкции.

## Контракт и поведение

- Соблюдайте маршруты и форматы из ТЗ: `/`, `/api/courses`, `/api/chat`, `/docs`.
- История хранится только в памяти страницы. В запросе максимум 20 сообщений по 2 000 символов, роли только `user`/`assistant`, последняя роль — `user`.
- Системное сообщение добавляет только сервер. История клиента не является источником фактов магазина.
- Оплата исключительно демонстрационная. Не собирайте реквизиты и не подтверждайте реальные покупки.
- При ошибках конфигурации, авторизации, квоты, сети и тайм-аута возвращайте понятные сообщения и статусы из ТЗ. Каталог должен работать независимо от чата.

## Настройки и секреты

- Через `python-dotenv` загружайте именно `.local.env` относительно `llm.py`, с `override=False`.
- Настройки: `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`. Поддерживаются `openai`, `deepseek`, `qwen`, `yandex`. Для YandexGPT дополнительно требуется `YANDEX_FOLDER_ID`: он должен совпадать с каталогом в URI модели `gpt://<folder_id>/<модель>` и передается клиенту как `project`. Переключение — изменением настроек и перезапуском.
- У каждого провайдера свой ключ. Проверяйте соответствие endpoint провайдеру до отправки запроса. Не используйте OpenAI-ключ для DeepSeek или Qwen.
- Не читайте и не печатайте содержимое `.local.env` для обычной диагностики. Не перезаписывайте заполненный файл образцом.
- Ключи доступны только серверу. Не включайте их в Git, HTML, ответы API, логи, документацию, тестовые фикстуры и сообщения пользователю.
- `.local.env` исключен из Git, `.local.env.example` содержит только заглушки. Не сохраняйте сырые ошибки провайдеров и тексты диалогов в логах.

## Команды после реализации

Запускайте команды из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
.\.venv\Scripts\python.exe -m pytest -q
```

Если `.local.env` отсутствует, скопируйте `.local.env.example` и заполните его локально. Подробности запуска и настройки документируйте в README.

## Проверки и отчет

- Обычные автоматические тесты подменяют вызов модели и не обращаются к внешнему API.
- Проверяйте каталог, валидацию, системный контекст, приоритет настроек, соответствие endpoint, ошибки провайдера и независимость каталога от чата.
- Отдельно проверяйте страницу и реальные диалоги по сценариям ТЗ.
- Реальный API-тест запускайте отдельно с ключом соответствующего провайдера. Не повторяйте платные запросы без необходимости.
- Не объявляйте интеграцию рабочей без реального подтверждения. Указывайте фактически выполненные проверки и ограничения; не считайте сетевой сбой доказательством неверного ключа.
- Не реализуйте приложение или новые функции при задании, ограниченном документацией.
